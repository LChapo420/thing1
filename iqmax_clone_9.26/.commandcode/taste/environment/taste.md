- **A grade is one course with one flat topic list — skills do NOT band the path.** This replaced the earlier per-skill banding design, which is arithmetically impossible to satisfy: requiring exactly N lessons for N topics *and* requiring every skill's band to hold that skill's topics cannot both hold, because N lessons split S ways is N/S each, so any skill with more than N/S topics can never get a lesson per topic, and the surplus lessons that would fix it are exactly the repetition being removed (math/arithmetic: 68 topics / 6 skills with a fractions skill needing 17 > 68/6). Banding also silently reported "68 lessons" while never reaching "GCF and LCM", because each band restarted at topic one. So `topics.js` has `gradeTopicList()` flattening the per-skill `content/syllabus.js` lists into one ordered list (entries carry `topic`, `covers`, `skill`, `skillIndex`), `lessonPosition` is always whole-path, and `topicFor` walks the list one step per lesson rather than scaling a position by a ratio — a ratio skips (14 lessons over 17 topics jumps 0,1,2,3,4,**6**) and left topics untaught with every check green. `config/path-length.js` now *solves* for the shortest path holding exactly the topic count instead of rounding to 50s and checkpoints; all 30 `pathLength: 250` literals are gone and real paths run 231–861. `npm run syllabus` is the check: topics = lessons = distinct topics, in order, no skips, no repeats. - The app has a three-layer design for question supply, and the layers are not interchangeable. **Shape** = the unit of variety (a generator that builds a real situation where distractors come from applying a *named* error to that sentence), **Content** = the authored/computed bank, **AI** = the per-learner layer that already exists: `regenerateItems` for every checkpoint retry, `generateItems` for focus and stretch, cached across learners. The reason AI cannot replace the bank is the product's own rule: a bank item's answer is computed or hand-checked and `npm run check` validates all 16,750, whereas a subtly-wrong AI-authored item becomes a graded wrong answer on a checkpoint that gates progression — and it would make the product depend on a vendor being up, which is the promise the bank exists to keep. So the correct response to "just generate every question with AI" is to lean harder on the existing per-learner AI layer and grow shapes, never to argue for replacing verified content with unverified generation. Confidence: 0.7

- **`services/grading.js` marked correct multiple-choice answers wrong.** The multiple-choice branch read a bare integer as an option **index** before trying the text, so on a question whose choices are `["1","2","3","4"]` with answer `"2"`, answering `2` was compared against `choices[2] === "3"` and a learner who picked the right option lost the point.
